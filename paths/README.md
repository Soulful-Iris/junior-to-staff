# Choose your learning path

Two paths share engineering concepts. Each has its own practice and definition of done.

| Path | Learn to | Start | Evidence you keep |
|---|---|---|---|
| **AI-assisted engineering** | Specify, direct, review, and verify AI-built software | [AI engineering](ai-engineering/README.md) | Running projects, adversarial checks, decisions |
| **Software engineering interviews** | Explain, design, implement, and defend your own solutions | [Interviews](interviews/README.md) | Working code, timed designs, failure analysis, project stories |

You can follow either independently. The interview path does not require completing P1–P5 or using AI. When following both, learn a concept in the existing chapters, build it with AI, then close the assistant and reproduce the reasoning and core implementation.

## The learning loop

1. **Predict.** Look at a visual's starting state. What changes next? Why?
2. **Learn.** Read the explanation and compare the failure with the mechanism that prevents it.
3. **Implement.** Run an example, change a constraint, and predict the effect before running again.
4. **Break.** Remove the mechanism and observe the original failure.
5. **Explain.** Close the page. Draw the request flow, state the invariant, and defend one rejected alternative.
6. **Revisit.** Repeat the explanation after a day and a week. Log gaps rather than rereading everything.
