# Scale and evolve the system

<section class="chapter-context" markdown="1">

## Change capacity, data and team decisions without losing the contract

More readers, a hot tenant, an optional AI feature, or a storage migration can each change the right design. The chapters keep the user’s outcome visible while you change where work and state live.

Choose the smallest change that addresses the measured constraint. Explain freshness, authority, cost, compatibility, and recovery where they matter. Finish with decisions other engineers can implement and maintain.
