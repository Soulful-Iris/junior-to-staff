# Teaching and audit implementation

Working branch: `feature/visual-learning-interview-paths`.
Source: [independent audit #1](https://github.com/Soulful-Iris/junior-to-staff/issues/1).

The first priority is the [shared learning experience](LEARNING-EXPERIENCE.md):
problem introductions, explicit contracts, reusable reasoning, individual project
pages, evolving diagrams, and at least forty complete coding problems. The table
below records implementation work; it does not imply that a planned item is done.

| Item | Required result | Status |
|---|---|---|
| Teaching priority | Both paths teach the starting problem, expected values, decisions, and visual follow-ups; bundled projects become individual pages | In progress |
| F1 | Separate candidate/assessor packs, unfamiliar variants, scoring anchors, scored senior/lead examples | Planned |
| F2 | Broader structures and reasoning; helper-free LRU, trees, lists, DSU, parsing, and DP progressions | Planned |
| F3 | Unfamiliar staged debugging/integration package and realistic review exercise with fixtures and keys | Planned |
| F4 | Executable synchronization, bounded admission, shutdown/cancellation, and deterministic concurrency tests | Planned |
| F5 | Correct PostgreSQL heap/index/HOT teaching; reproducible isolation and query-plan lab | Planned |
| F6 | Runnable full-stack slice with draft/version races, authorization, pagination, and browser checks | Planned |
| F7 | Correct cache/replica guarantees; scoped coordination, outage budgets, and failure tests | Planned |
| F8 | Leases/fencing, external effects, recovery, and explicit crash boundaries beyond the atomic-result lab | Planned |
| F9 | Cached-link revocation contract, warm-cache test, and bounded authorization behavior | Planned |
| F10 | Migration partial writes, reconciliation/repair, DNS rollback limits, and incremental value | Planned |
| F11 | Correct SLO units, alert logic, overload classification, retry counts, and exercises | Planned |
| F12 | Correct API Gateway enforcement boundary; replace App Mesh recommendation and verify current AWS guidance | Planned |
| F13 | Falsifiable evaluation without required current failures; imbalance and judge-quality exercises | Planned |
| F14 | Traceable evidence, explicit dates/limits, honest project inventory, and navigable scope | Planned |

Updates are committed in reviewable checkpoints. Validation and remote commit
confirmation are recorded as work lands; no AWS deployment is required to read or
run the local curriculum.
